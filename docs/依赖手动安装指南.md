### 如果 `better-sqlite3` 编译失败

它默认下载预编译二进制；失败时才会本地编译（需要 VS Build Tools）。优先重试预编译：

```powershell
npm rebuild better-sqlite3 --build-from-source=false
```

仍失败再装编译工具链：

```powershell
npm install --global windows-build-tools
# 或手动安装 Visual Studio Build Tools 勾选「使用 C++ 的桌面开发」
```

## 2. 前端依赖（关键：两个必需参数）

前端是这次安装的难点，**有两个坑，必须带对应参数**：

### 2.1 标准命令（推荐直接用这条）

```powershell
cd C:\Users\Dong\weekly-report-platform\client
npm install --legacy-peer-deps --no-audit --no-fund
```

**`--legacy-peer-deps` 是必需的**，不加会直接报 `ERESOLVE could not resolve`：

```
npm error ERESOLVE could not resolve
npm error While resolving: @tiptap/extension-collaboration-cursor@2.27.x
npm error Found: react@18.3.1
npm error Conflicting peer dependency ...
```

原因：`@tiptap/*` 2.27+ 的 peer 声明与 React 18 的解析规则冲突（npm 7+ 默认严格模式会拒绝）。这是 Tiptap 生态的已知问题，`--legacy-peer-deps` 是官方推荐解法，不影响运行。

### 2.2 如果卡住不动（超过 5 分钟无进度）

镜像源对 `esbuild` 的原生二进制、`prosemirror-*` 系列包命中率低，容易卡在 `postinstall`。按顺序试：

**方案 A — 换官方 registry**（本次实测有效）
```powershell
cd C:\Users\Dong\weekly-report-platform\client
npm install --registry=https://registry.npmjs.org --legacy-peer-deps --no-audit --no-fund
```

**方案 B — 跳过生命周期脚本，先把依赖树装齐，再单独补 esbuild 二进制**
```powershell
npm install --ignore-scripts --legacy-peer-deps --no-audit --no-fund
# 再手动触发 esbuild 的二进制下载
cd node_modules\esbuild
node install.js
cd ..\..
```

**方案 C — 换包管理器**（pnpm 对这种大依赖树更稳、更快）
```powershell
npm install -g pnpm
cd C:\Users\Dong\weekly-report-platform\client
pnpm install
```
pnpm 默认就是宽松 peer 策略，不需要 `--legacy-peer-deps`。

**方案 D — 彻底重来**（前一次安装残留会导致后续静默失败，这个坑本次踩过）
```powershell
cd C:\Users\Dong\weekly-report-platform\client
Remove-Item -Recurse -Force node_modules -ErrorAction SilentlyContinue
Remove-Item -Force package-lock.json -ErrorAction SilentlyContinue
npm cache clean --force
npm install --registry=https://registry.npmjs.org --legacy-peer-deps --no-audit --no-fund
```
> 重要：中途 `Ctrl+C` 掉的安装会留下不完整的 `node_modules`，之后再 `npm install` 可能**无任何输出直接退出**（看起来像什么都没干）。遇到这种情况必须先清空再装。

### 2.3 esbuild 二进制单独处理

`vite` 依赖 `esbuild`，而 esbuild 需要一个平台专属的 `.exe`。检查它在不在：

```powershell
Test-Path C:\Users\Dong\weekly-report-platform\client\node_modules\@esbuild\win32-x64\esbuild.exe
```

注意路径是 `@esbuild\win32-x64\esbuild.exe`，**不是** `...\bin\esbuild.exe`（本机实测约 9.9 MB）。

返回 `False` 时手动补：

```powershell
cd C:\Users\Dong\weekly-report-platform\client
npm install @esbuild/win32-x64@0.21.5 --no-save --legacy-peer-deps
```

版本号要和 `node_modules\esbuild\package.json` 里的 version 严格一致（本项目是 `0.21.5`），否则 esbuild 会报版本不匹配。

完全下不下来时，可以从别的机器拷 `esbuild.exe` 过来，然后用环境变量指定路径绕过校验：

```powershell
$env:ESBUILD_BINARY_PATH = "C:\path\to\esbuild.exe"
npm run build
```

## 5. 启动

```powershell
cd C:\Users\Dong\weekly-report-platform
$env:PORT = "8020"
node src\index.js
```

浏览器打开 **http://localhost:8020** ，默认账号 `admin` / `admin123`。

后端会自动托管 `client\dist`，所以**只需启动一个进程**，前后端同一个端口。

> 注意：`client\dist` 必须在后端启动**之前**就存在，后端启动时才会挂载静态目录。改了前端代码要 `npm run build` 后**重启后端**。

### 前端热更新开发模式（改前端代码时用）

开两个终端：

```powershell
# 终端 1：后端
cd C:\Users\Dong\weekly-report-platform; $env:PORT="8020"; node src\index.js

# 终端 2：前端 dev server
cd C:\Users\Dong\weekly-report-platform\client; npm run dev
```

访问 dev server 给出的地址（默认 `http://localhost:5173`），`/api` 和 `/collab` 已在 `vite.config.ts` 里代理到 8020。

## 6. 端口冲突

8020 被占用时先查再决定：

```powershell
Get-NetTCPConnection -LocalPort 8020 -ErrorAction SilentlyContinue |
  Select-Object LocalPort, OwningProcess,
  @{n='Process';e={(Get-Process -Id $_.OwningProcess).ProcessName}}

# 确认是本项目的旧进程后再结束
Stop-Process -Id <PID> -Force
```

> 8000 端口是你的「备件价格监控中台」(FastAPI) 在用，本项目已避开，固定用 8020。

## 7. 本次安装踩到的坑（速查）

| 现象 | 原因 | 解法 |
|---|---|---|
| `ERESOLVE could not resolve` | Tiptap 2.27 与 React 18 的 peer 严格解析冲突 | 加 `--legacy-peer-deps` |
| 安装卡住 20 分钟无输出 | 镜像源对 esbuild 二进制 / prosemirror 系列命中率低 | 换官方 registry，或 `--ignore-scripts` 后手动补 |
| `npm install` 立即退出、无任何输出 | 上次中断的安装留下残缺 `node_modules` | 删 `node_modules` + `package-lock.json` 后重装 |
| `esbuild.exe` 找不到 | postinstall 被跳过或下载失败 | 单独装 `@esbuild/win32-x64@0.21.5`，或用 `ESBUILD_BINARY_PATH` |
| 访问 `:8020` 只有 API 没有页面 | 后端启动时 `client\dist` 还不存在 | 先 `npm run build`，再重启后端 |
